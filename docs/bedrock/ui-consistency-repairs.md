## Scope and preserved behavior

The [surface classification](ui-consistency-repair-evidence/surface-classification.json) records candidates and intentional custom compositions. Native forms, fieldsets, lists and disclosures were retained. No broad global radius reset was added. Shader/artwork samples, fixed experiment geometry, maps, sidebar embedding viewports, and ExampleCard’s documented Chromium clipping exception remain specialized compositions.

The tooltip bridge necessarily renders its fallback arrow at the child boundary because the installed Bits implementation consumes the content ID. This is confined to the Bedrock wrapper and covered for caller-supplied IDs and child snippets; recheck it when upgrading Bits.

The integration preserves all pre-existing workspace files, dependency manifests and frozen `src/lib/shadcn` sources. Three isolated worker branches were reviewed against a snapshot of the existing dirty workspace. Changes are uncommitted.

## Remaining limits

This is verification of the repaired findings, not a second exhaustive interaction audit. The original report’s partial/uninspected state matrices still apply. Component preview coverage checks loading, layout and runtime errors; it does not exercise every option or keyboard sequence in every primitive. External media playback is excluded from the repair regression batch. Calendar and video contrast fixes do not establish accessibility compliance for the entire product.

T3 collaborative navigation, DOM inspection and Form submission worked; snapshot calls repeatedly failed. Browser regression tests use the repository’s existing shared-Chrome harness and isolated contexts. Screenshots from those tests are identified as test evidence, not T3 captures.

The audit’s earlier motion-policy unit failure was caused by running Vitest under the container’s production environment. The project’s `test:unit` script explicitly sets `NODE_ENV=test`; that supported command passes without a policy implementation change.
