# Component family motion plan

Date: 2026-10-01. Implemented: 2026-10-02. See the [implementation record](component-motion-implementation.md) for APIs, coverage and verification.

Scope: one row per top-level directory in `src/lib/bedrock/ui`. Compound parts belong
to their family: Card includes its header, content and footer; Chat includes its
composer, messages, pickers and disclosures. `backgrounds` is included as shared
infrastructure so the inventory is complete. Rows define the family-level contract. The implementation record distinguishes
new APIs from existing behavior retained after audit.

## Baseline and recipes

Use the current [motion guide](motion.md), [motion contract](motion-contract.md),
and [canonical tokens](../../src/lib/bedrock/motion/tokens.ts). Preserve the
Astryx-aligned values. Astra is the engine for coordinated presence, shared layout,
gesture physics and animated values; simple state/indicator feedback stays in CSS.
This document does not restore the superseded architecture review's ownership or
timing proposals and does not authorize a token change.

| Recipe              | Token vocabulary / proposed mapping                                              | Intended behavior                                                                                                                                                                                                   |
| ------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Entry easing remains `(0.23, 1, 0.32, 1)`; exit remains `(0.3, 0, 0.6, 0.6)`.
Use the existing move/drawer curves for their roles. A recipe selects existing
tokens; it does not mean every property must animate for the entire duration.
The `swap` spring is 183/23/1. The 400/500ms values are canonical compatibility
windows: legacy helpers normalize spring samples to these durations. In contrast,
[the Astra adapter](../../src/lib/bedrock/motion/astra-presets.ts) passes spring
physics without a duration for content replacement and relocation. Native Astra
settling is not guaranteed to take 400/500ms. Keep this distinction when choosing
an owner; this plan does not silently retune either path. No new public numeric
animation props are proposed.

The Resax influence is the combination of opacity, small translation and blur
settling to sharp, not its slower timing or 14px blur. Proposed small-surface blur
is 2–4px and disclosure copy 2px at most; these are effect-local limits, not new timing tokens. Blur is optional, never a dependency for meaning or legibility.

## Rules shared by all families

- Default functional UI motion follows a meaningful interaction or new event, not
  hydration, scrolling into view, or incidental remounting. Initial content is
  readable. Explicit decorative modes (signature drawing, shaders, shimmer and
  marquee) may start with their presentation; essential information is available
  throughout, reduction is static, and remounts must not cause gratuitous replay.
- One family entrance owns the surface. Nested header/body/footer components do
  not each replay their own entrance. A child popup opened later owns its entrance.
- Text is a whole block by default. No word/letter choreography in functional UI;
  explicit editorial compositions can opt into Astra text effects separately.
- Menus default to one whole-content entrance. A deliberately selected expressive
  variant may stagger tiny icon/decorative motion in at most four action rows,
  with at most 20ms spacing, within the existing 200ms popup budget. All labels
  remain sharp and visible as the panel appears; the first/autofocused row never
  staggers. Skip on keyboard opening, submenus, selects, filtering and virtual
  lists. Settle on pointer hover or focus/highlight changes; never animate the
  target away from input. Regression fixtures exercise these limits.
  Nothing waits for animation to accept focus or activation.
- Keep blur on one visual layer only. Do not blur a panel and its descendants
  simultaneously; prefer a stable surface and lightly animated inner content.
  Also use one opacity owner: the current `reveal()` already fades the outer
  content, so an inner fade must replace that fade rather than multiply it.
  Exclusive accordion handoffs use coordinated matching height clocks/curves,
  preserving combined flow space during simultaneous close/open.
- Selection, validation, focus, announcements and direct pointer tracking update
  immediately. Focus outlines do not fade in. Urgent text is immediately legible.
- Rapid reversal/retargeting starts from the current appearance. Do not queue
  stale transitions, replay full entrances on resize, or delay navigation.
- Exit motion never delays the semantic action. Exiting interactive content is
  inert and hidden from assistive technology; preserve a meaningful focus target.
- Reduced motion resolves to the latest readable state immediately, including
  opacity, blur, repeat loops and retained exits. OS, application and portal policy
  agree; changing the preference while running also settles the motion.
- Decorative loops require an explicit use case and pause when offscreen or the
  document is hidden. Provide pause controls where a persistent moving presentation
  needs them. No continuous motion is added to ordinary controls.
- Existing gesture/media/chart owners retain their own direct-manipulation logic.
  Do not place another transform, retention or physics owner on the same property.

## Independent challenge and resolutions

The user requested an adversarial subagent review after the first complete table.
The reviewer inspected the 129 family rows, current motion documentation and
relevant source, then raised eight objections. The author answered with proposed
changes and defended retaining a limited expressive option. The reviewer accepted
the compromises with the readability/focus conditions below. This is design
agreement, not empirical validation of the proposed appearance.

| Challenge                                                                        | Discussion and final decision                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| “400/500ms is not a promise about native Astra springs.”                         | Accepted. Distinguish duration-normalized compatibility helpers from the physics-only native adapter. No token or adapter change.                                                                                                                                     |
| “A compact-label swap is too broad a recipe for month grids, steps and tabs.”    | Accepted. Those panels commit immediately and may opt into a bounded Panel change using existing enter/exit tokens, with separately coordinated shell reflow.                                                                                                         |
| “Accordion already fades; adding an inner fade doubles opacity attenuation.”     | Accepted. One opacity owner, coordinated exclusive height handoffs, no second independent fade/retention layer.                                                                                                                                                       |
| “Even 2px of blur delays reading accordion content.”                             | Partially accepted. Default stays sharp. Author retained an explicit short-prose option to preserve the requested visual; reviewer accepted early sharpening, no dense/interactive copy, and immediate settlement on focus.                                           |
| “Row staggering delays menu scanning and makes focused targets move.”            | Default changed to a whole-menu entry. Author defended an explicit expressive mode; final mode staggers only tiny decorative/icon movement, keeps labels visible/sharp, excludes the first/focused row and settles on interaction. Select and submenus never stagger. |
| “The hint-exit token says 100ms, but current tooltip CSS dismisses immediately.” | Accepted. Preserve prompt dismissal; document the unused token separately rather than silently changing the interaction.                                                                                                                                              |
| “410ms overlay timing must not hold readable dialog content back.”               | Accepted. It is the shell/backdrop budget; text and autofocus targets become clear promptly. Alert dialogs do not blur or stagger.                                                                                                                                    |
| “The no-initial-entry rule contradicts explicitly animated decorative families.” | Accepted. Functional UI starts readable; explicitly chosen decorative presentations may begin their intended effect with static reduced-motion behavior and no gratuitous replay.                                                                                     |

Reviewer verdict after discussion: no remaining blocking contradiction in the
resolutions; the constrained sharpen/movement options preserve the Resax character
without delayed menu readability or competing animation owners.
