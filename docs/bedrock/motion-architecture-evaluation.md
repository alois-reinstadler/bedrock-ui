# Route motion evaluation and architecture decision

2026-09-22. Read alongside the [100-component audit and motion policy](motion-architecture-review.md). The audit preceded implementation. This revision replaces the earlier incomplete evaluation; production component implementations and existing engines have not been migrated.

**Recommendation: use native CSS for ordinary component visuals, small independent helpers for measurement/presence, the existing dedicated local-layout layer where coordination is necessary, and a separate JS route coordinator with part-specific WAAPI playback.** The expanded representative prototype now exercises the route requirements that the first version deferred. Neither Bedrock's geometry-only, group-local handoff nor Astra's browser View Transition wrapper supplies this route architecture.

[Open the evaluated prototype](http://100.64.0.2:4095/demo/motion-route-prototype/list). It uses real SvelteKit list/detail routes and browser history. Each story has a surface, image viewport/bitmap, and naturally typeset title. Both pages have independently scrolling containers, rounded nested clipping, and sticky content. Controls expose slow playback, app reduction, late content, typography changes and a top-layer modal. The managed preview remains running; a container restart requires restarting it.

The evaluated implementation is [coordinator.ts](../../src/lib/site/motion-route-prototype/coordinator.ts), with independently tested [geometry](../../src/lib/site/motion-route-prototype/geometry.ts). Ordinary components import neither this coordinator nor its route lifecycle. It never invokes `startViewTransition` and has no custom playback RAF loop: JS samples paths once into WAAPI keyframes, then runs for lifecycle, readiness and event-driven remeasurement.

## Concrete supported contract and tradeoffs

- **Ownership and nesting:** scoped entity identity plus one surface, image and title; nearest-entity filtering prevents nested records from donating each other's parts. Visual parts are flattened into viewport coordinates. Surface contains paint only; text and image do not inherit surface scaling. Generic production registration should expose this contract explicitly rather than treating every arbitrary DOM subtree as renderable.
- **Clipping and stacking:** up to eight ancestor overflow clips, rectangular or uniformly rounded with pixel radii, with a viewport clip. The prototype reads the top-left radius for each clip; unequal/percentage radii and individual CSS scale/rotate properties are outside its evaluated contract and are not comprehensively detected by its guard. Source and destination clip chains interpolate together. Layer order is surface < image < title, route scene at 30, persistent navigation at 40, native dialogs in the browser top layer. Arbitrary masks/clip-paths, 3D, scale/rotation ancestors, ambiguous/missing registrations and unavailable source geometry use an entity-level fade/settlement. Translation ancestors are supported. A masked or virtualized missing source is not secretly treated as a visible shared element.
- **Interruption:** positions, clipping, bitmap geometry, opacity and trajectory velocity are read/frozen before cancellation. Same-identity navigation transfers those visual layers to the new session; a revision/generation check makes old completion callbacks harmless. Hermite trajectories end at rest and inherit existing velocity, so reversal can briefly continue in the old direction. This is intentional momentum, not arbitrary bounce. A destination still waiting on readiness holds the current visual in place; that bounded hold pauses velocity rather than extrapolating toward stale geometry.
- **Text:** changed font sizes/wrapping fade through two natural typesettings. There is a brief lower-contrast interval. This does not morph glyphs. If a third distinct typesetting arrives during interruption, the weaker old copy is dropped and its opacity transferred to the survivor before introducing the next; this bounded approximation can change fine text detail. The same two-copy bound applies to a third distinct bitmap. It avoids unbounded retention; it does not promise exact compositing of unlimited interrupted assets.
- **Images:** bitmap cover geometry follows each asset's own intrinsic ratio and the target object-position. The source asset remains until destination decode. Different art-directed images crossfade, which preserves continuity of framing but cannot preserve identical image content. At the 800ms readiness budget, reveal reserved destination layout and its placeholder; a late image fades in through ordinary CSS. A failed image keeps that placeholder. URL/navigation is never held until visual playback finishes.
- **Layout and history:** Kit owns route data, document scroll and focus. The public Kit 3 snapshot helper restores independently named inner scrollers per history entry before target capture. Geometry is observed on destination parts and scroll containers; scroll, resize and font completion schedule a batched retarget. Destination content reserves its normal layout boxes; the coordinator never animates surrounding layout as a side effect of moving its proxies.
- **Reduction and failure:** OS reduction is the minimum; an application setting may add reduction. Changes cancel the session, reveal the latest DOM and remove temporary ownership. Missing animation support or playback exceptions leave navigation usable. Pagehide, pageshow, disposal and supersession clean up ownership. Unmatched content uses a short opacity reveal; no route-wide zoom or spatial fallback.

This is a positive architecture recommendation for the representative contract, not a claim of universal CSS rendering or full browser certification. The executed browser is shared **Chrome 152**. Firefox/WebKit compatibility and device-scale performance still need normal release qualification; they are not being substituted with untested claims. The production local-layout engine remains unchanged; replacing that backend is a separate decision requiring its own equivalent-behavior evidence.

## Reproduction and verification

1. Open the prototype and wait for hydration. At 1280×1000 with normal network and no reduced-motion preference, evaluate the function in [browser-suite.js](motion-architecture-evidence/browser-suite.js) through Chrome MCP. It performs real link/history navigation, uses controlled WAAPI times for midpoint assertions, and returns pass/fail records.
2. Run [interruption-suite.js](motion-architecture-evidence/interruption-suite.js) for 25/50/75% position/velocity measurements and twenty round trips. Use Slow inspection only for inspection; normal route playback is 360ms, retargeting 240ms.
3. For network reproduction, visit a detail URL with `?art=1&fresh=<unique-value>` under Fast 3G and Slow 3G in Chrome MCP. `art` selects a different real bitmap; `fresh` makes an uncached image URL. Check source retention at 120–150ms, placeholder after 900ms for the slower case, actual Resource Timing/transfer size and stable box after decode. `?broken=1` deliberately requests a missing image. The earlier synthetic `ready` control remains available but is not the evidence for real network handling.
4. Chrome MCP's `emulate` tool does not expose reduced motion. Actual emulation was applied through an owned DevTools frontend tab opened via MCP at `http://127.0.0.1:9222/devtools/inspector.html?ws=127.0.0.1:9222/devtools/page/<owned-target-id>`. Inside that frontend, import `./core/sdk/sdk.js`, get `TargetManager.instance().primaryPageTarget()`, then call `emulationAgent().invoke_setEmulatedMedia({features:[{name:'prefers-reduced-motion',value:'reduce'}]})`. Verify the application media query and CSS, navigate before/during reduction, restore `no-preference`, and close the owned frontend. This changes browser media emulation; it does not monkey-patch `matchMedia`.
5. For BFCache, pause an active route scene, attach a `pageshow` listener recording `persisted` and a random instance token, navigate the same tab to `/motion-route-prototype-leave.html`, then browser back. The same token plus persisted restoration and zero hidden/layer nodes distinguishes BFCache from a fresh load. The repeated `true` entries in this run are from two test listeners, not two restored documents.
6. For resize, keep the same mobile/desktop emulation flag while changing viewport dimensions; changing the flag itself can reload Chrome's page and is not a resize test. Exercise the late-content/typography controls and top-layer dialog while Slow inspection is active.

The focused server suite passed **55 tests in 8 files**, including intrinsic cover geometry and Hermite endpoint/velocity tests. Svelte autofixer returned no issues/suggestions; `pnpm check` reported zero errors/warnings; focused ESLint and production build passed. The build reports an existing adapter configuration deprecation. Browser fault tests intentionally include a missing image; normal production navigation must have clean console and successful document/image requests.

Earlier files without the `expanded-` prefix describe the first evaluation only; the records linked above supersede its deferred-core-requirement verdict. The initial attempt to hold requests through a second DevTools Fetch dispatcher was not a reliable throttle and was discarded; the recorded image evidence uses Chrome's actual network throttling and Resource Timing.

The audit's removal column remains a migration proposal. No production CSS conversion, API deletion or local engine replacement is claimed here. The next implementation can proceed by responsibility without coupling ordinary components to route orchestration.
