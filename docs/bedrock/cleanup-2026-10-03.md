# Astryx motion consolidation and Feedback cleanup

## Scope and design authority

Astryx supplies the motion design system. Astra Motion is an implementation
engine. This cleanup preserves every existing `motionPresets` duration, easing
control point and spring parameter; it does not retune the design system.

The starting working tree already contained 436 modifications, 3 deletions and
206 untracked entries. Those changes were retained. This record describes the
incremental cleanup, not the whole working-tree diff.

## Dev baseline

The existing dev preview initially reported `lifecycle_outside_component` from
SiteHeader after SvelteKit's generated modules changed. On this pass it returned
HTTP 200, hydrated the homepage, and logged no browser warnings or errors. The
fault did not reproduce after regeneration or after the final production build. No speculative SiteHeader fix was
made; the original fault's precise cause remains unproven.

Keep type generation, unit tests and production builds sequential because they
share SvelteKit's generated output. A healthy older production preview alone is
not evidence that the current source builds.

## Changes

- Consolidated surface state rules in `styles.css`. Each family selects visual
  and retention clocks; Bits still owns lifecycle and focus. Removed superseded
  dialog, alert-dialog and sheet animation utilities. Six consumers needed only
  class-order formatting after the Tailwind utility registry changed.
- Preserved existing immediate tooltip dismissal and early readable dialog
  content as documented component policies. The Astryx seeds remain unchanged.
- Named the existing AsyncButton label tween `labelReplacement`, distinct from
  the physics-based `contentReplacement` recipe. Reused live value settlement.
- Removed the video template's animation wait from `onNavigate`. Its own exit and
  entrance use Astryx timings; OS and application reduction cancel owned paint.
- Album transitions now select Astryx enter/exit curves and settle immediately
  when reduction changes, including during a stagger delay. Music card feedback
  uses shared tokens. Composition delays remain separate from animation speed.
- Fixed live-reduction tagging for transition CSS with or without a trailing
  semicolon. Regression tests cover active album fades and delayed entrances.
- Updated the current motion guide, public docs page and outdated surface demo
  descriptions. The old layout contract points to current component policy.
- Extracted Feedback toolbar, tray and composer into controlled internal views.
  Native refs, selection, text restoration, storage and focus commands stay in
  the existing controller. Shared styles are restricted to `.feedback-root`.
  Feedback's controller/view file shrank from 2,102 to 1,132 lines. Its
  feedback and placement transitions now consume the shared tokens. Expanded or
  disabled controls no longer show a tooltip over the open panel.

The production geometry regression test now measures AsyncButton's current
sizing shell. Its old `Swap` selector had become stale before this cleanup.

## Engine and bundle decision

Keep the legacy layout implementation behind its existing compatibility API.
Production components already use focused helper or Astra subpath imports, and
the graph verifier rejects accidentally including the legacy layout engine in
ordinary consumers. Rewriting its nested projection, interruption and retained
exit behavior has no demonstrated benefit in this cleanup.

The following measurements use the repository's existing consumer fixtures.
Standalone bytes include dependencies. Warm bytes come from one multi-entry
build after its fixed engine reference is loaded; they are not subtracted from
independently gzipped bundles and are not predictions for every application.

| Fixture     | Standalone gzip | Engine-warm gzip | Standalone ceiling | Warm ceiling |
| ----------- | --------------: | ---------------: | -----------------: | -----------: |
| Button      |        42,232 B |         22,707 B |           47,000 B |     25,000 B |
| AsyncButton |       102,726 B |         34,564 B |          114,000 B |     39,000 B |
| AvatarStack |        85,471 B |         18,924 B |           95,000 B |     21,000 B |

`scripts/motion-budgets.json` stores rounded regression ceilings above this
baseline. `motion:verify` enforces both fixture sizes and the existing import
boundaries. Re-examine import graphs before increasing a ceiling.

AsyncButton's standalone fixture increased by 224 B from the initial audit when
it adopted shared live-settlement handling. This is a small, explicit correctness
cost; this pass makes no bundle-reduction claim. A later engine change should
compare interruption, focus and live-reduction behavior alongside cold/warm bytes.

## Recommended follow-up

1. Make the shared-browser unit runner reliable before expanding the motion
   migration. Reproduce the WebSocket/iframe failures independently; the shared
   Chrome service remained healthy, so a browser restart is not a demonstrated fix.
2. If Feedback grows further, extract text-edit restoration and pointer-selection
   state behind narrow controller APIs. Keep focus and DOM restoration regression
   coverage while doing so; avoid moving state merely to reduce line count.
3. Require measured consumer savings and parity for interrupted layout, retained
   exits, focus, and live reduction before replacing the compatibility engine.
   Extend the bundle fixtures when a new consumer introduces a different import path.
