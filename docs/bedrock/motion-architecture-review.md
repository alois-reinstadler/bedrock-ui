# Bedrock motion architecture review

Initial audit: 2026-09-21. Updated after expanded prototype evaluation: 2026-09-22. Status: architecture recommendation with tested route prototype; production components are not migrated.

The subsequent [prototype evaluation](motion-architecture-evaluation.md) records the expanded browser evaluation, supported contract and explicit visual tradeoffs. Production components have not been migrated.

The default should be native CSS. Keep measurement and exit retention separate from animation playback. Preserve an explicit JS coordination layer for shared layout and route transitions, with the evaluated JS session coordinator plus WAAPI approach for routes. Neither existing engine is the route solution.

This review follows the actual Bedrock wrappers into `src/lib/shadcn/ui`, reads the vendored Astra runtime, and includes static components. Existing tests describe current behavior; they do not require retaining the implementation. Recommendations below are proposed behavior, not claims that migrations have been performed.

## Main findings

1. Most controls already use CSS. Eight Bedrock UI families have runtime dependencies on the motion barrel: Accordion, AsyncButton, AvatarStack, ChatComposer, DataTable, Lightbox, Outline and Tabs. Their needs differ substantially.
2. Tabs, Outline and DataTable animate a single measured indicator. They need geometry measurement, not general FLIP, group discovery, shared IDs, spring sampling or subtree projection. CSS can interpolate the resulting numeric position and dimensions, including interrupted changes. This gives up the existing sampled spring overshoot, not the sliding indicator.
3. `reveal`, `Swap` and `autoSize` are not all custom per-frame engines. Svelte generates WAAPI for transition `css` callbacks; `autoSize` measures and starts WAAPI. Remove unnecessary abstraction, not useful lifecycle guarantees.
4. `autoSize` observes mutations, not intrinsic size changes themselves. Image decode, font changes and some container resizes can escape it. Replace its observation strategy with a measured inner content box; do not claim `interpolate-size` animates arbitrary auto-to-auto content changes.
5. Local shared layout is real functionality. Avatar membership packing and deliberately opted-in list reorders can keep a dedicated layout coordinator. Ordinary layout changes should not automatically animate everything nearby.
6. Bedrock's local engine stores geometry for 480 ms within one group. Its contract explicitly excludes navigation and simultaneous shared owners. Astra has a route API, but its implementation uses `startViewTransition`, assigns snapshot names and calls `skipTransition` on supersession. Neither implements the requested JS-owned image/surface/title route continuity.
7. Motion policy is split: CSS tokens, legacy OS-only policy, Astra configuration, upstream utility defaults and third-party gestures. `motion-hint` ignores the declared exit duration; several inherited animations do not use Bedrock tokens. Sharing duration values alone would leave different movement, easing, reversal and exit behavior.

## Recommended coherent policy

Use one semantic policy source to generate CSS custom properties and JS values. The route prototype validates the geometry, text handoff, interruption and reduced-motion behavior below; ordinary component values are recommendations, not a claim that every component has already been migrated or visually retuned.

| Role                      | Duration                                           | Curve / physical meaning                                                                              | Movement and composition                                                                                       |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Press                     | 80ms down, 140ms release                           | Decelerate `(0.2,0,0,1)`                                                                              | At most 1px translation of inner visual, not label scaling; focus/activation immediate                         |
| State                     | 140ms                                              | Same deceleration                                                                                     | Color, border, opacity, shadow; no geometry                                                                    |
| Hint                      | 120ms enter, immediate exit                        | Decelerate                                                                                            | Opacity; at most 4px from anchor; preserve hover delay separately                                              |
| Popup                     | 180ms enter, 120ms exit                            | Enter `(0.2,0,0,1)`, exit `(0.4,0,1,1)`                                                               | 4px away from anchor; avoid whole-text zoom; backdrop opacity independently eased                              |
| Local relocation / reveal | 240ms                                              | Symmetric smoothstep `(0.333333,0,0.666667,1)` for coupled expanding/collapsing geometry              | Indicator position/size, bounded height; no bounce; siblings use real reflow OR FLIP, never both on same axis  |
| Content replacement       | 180ms visual; up to 240ms shell                    | Complementary opacity; shared progress for same content role                                          | Roll at most 8px for short labels; large copy replaces/fades, never scales; no stagger of typing/search        |
| Sheet / large shell       | 300ms enter, 220ms exit                            | Decelerating settle                                                                                   | Edge-relative motion, fixed inner text width, backdrop coupled to surface progress                             |
| Shared route              | 360ms initial path; 240ms retarget                 | Smoothstep from rest; cubic Hermite with inherited velocity on interruption; shared geometry progress | Independent text rendering; no route-wide zoom; unmatched content fades briefly without moving the entire page |
| Gesture settle            | Defined by distance/velocity, not a fixed duration | Non-overshooting settle by default; real spring only for explicit elastic interaction                 | Direct pointer tracking before release; engine owns axis; no CSS transition fighting it                        |

The common feel comes from immediate semantic response, restrained distance, stable text, a shared phase for related geometry, and consistent interrupt behavior. It does not require every property to use one easing. Surface, crop and child position must agree geometrically; opacity can occupy only part of that same timeline. Avoid the current mixture of long swap delays, 500ms bouncing indicators, short default shadcn transitions and 208px menu slides.

Interruption: CSS transitions naturally retarget from computed values; prefer them for persistent controls. Keyframes restarting is a deliberate exception for fresh notifications, not a default for repeatedly toggled surfaces. WAAPI coordination must read the current rendered state before canceling, transfer ownership in one task, then retarget. Position continuity is mandatory when feasible. The route coordinator carries analytic position and velocity into a new Hermite trajectory; sampled WAAPI frames approximate that path. Browser measurements at 25/50/75% showed zero position jump and less than 0.02 px/ms difference across 8ms velocity samples. Native CSS controls promise continuous position, not derivative continuity. Gesture backends must preserve release velocity explicitly. Never discard rapid navigation input just because motion is active. Never wait for visual completion to update URL, selection or live-region state.

Reduced motion: one effective policy across CSS and JS, with OS reduction the minimum. Optional application reduction can add to it; normal components must not override the OS with “always”. No spatial interpolation, parallax, zoom, pulse or spin; commit geometry immediately. Default content replacement immediate, optional <=80ms opacity only where it aids recognition. Cancel an active animation when the preference changes and reveal the latest valid destination in the same turn. Remove visual layers, inline ownership and pending timers; do not leave focus trapped or navigation waiting. CSS 0.01ms is only a compatibility aid for lifecycle consumers, not a blanket fix for independent WAAPI/library playback.

## Recommended route coordination architecture

Install one coordinator in a persistent SvelteKit layout. SvelteKit owns navigation/data/history; the coordinator owns temporary visuals and participant readiness. Use `onNavigate` to capture immediately before commit and its post-DOM callback / navigation completion for target discovery. Do not await navigation completion inside a promise that prevents navigation from proceeding. Never delay routing for the full animation.

Participants register an identity such as `record:42` plus part `surface`, `image`, `title`, a namespace, logical parent, rendering strategy, clip policy and layer order. Separate logical identity from DOM instance identity. Detect ambiguous live registrations and skip only the ambiguous pair. Match a visible source to a committed destination; do not turn an unpainted intermediate mount into the source of the next transition.

1. Capture the currently rendered source (or active overlay) with viewport box, opacity, radius, source asset, crop, text style/line layout and clip chain. Keep only the selected entity and a bounded amount of visual data.
2. Create inert, aria-hidden, pointer-transparent visual layers in a persistent overlay. Keep normal layout boxes in flow. Suppress duplicate source/destination paint atomically before they can flash; do not clone interactive DOM with IDs, focusable descendants or live regions.
3. Commit the actual route and scroll position. Reserve destination media aspect ratio and text space; mount the layout shell with known data immediately. Measure after layout and intended scroll restoration, before uncovering destination parts.
4. Build part-specific WAAPI tracks, start them on one document timeline, and clean up on completion, cancellation, error, reduction, pagehide or coordinator disposal. A frame callback for capture/retarget is fine; ordinary playback should not need a custom RAF loop.

**Surface:** independent paint-only rounded background/border/shadow. Animate box geometry without scaling its text descendants. Width/height animation on a few isolated overlay boxes is an acceptable bounded cost; optimize with transform and corrected radius only if profiling justifies it.

**Image:** separate clipping viewport and bitmap. Compute cover/contain scale and translation from intrinsic dimensions and object-position at both endpoints. Interpolate the image transform and clipping rectangle from the same progress. This avoids abruptly switching object-fit crops or stretching the bitmap. For different art-directed assets, crossfade decoded assets within the moving clip; visual identity is then approximate and must be disclosed. Never replace the bitmap halfway through simply because a request finished.

**Title:** translate at natural typography size; never nonuniformly scale glyphs with the surface. If font size/wrapping changes, use two separately typeset title layers with a controlled opacity handoff and an aligned anchor. For identical text metrics, move one layer. A crossfade between different line wraps is an explicit compromise, not a claim to morph glyphs. Avoid two full-opacity titles and avoid an empty handoff frame.

**Nested elements:** use a logical scene tree, but flatten independently rendered parts into one coordinate system for playback. Surface must not contain a second copy of title/image. If actual nested projection is used, subtract parent motion exactly once; parent clip remains a separate inherited constraint. Ordinary component transforms must live on a different wrapper from a coordinator-owned transform.

**Clipping:** record viewport/scroller intersection and border-radius at capture. A registration chooses whether its clip interpolates into the destination clip or remains inside a persistent container. Do not assume teleporting into a body portal should escape every clip. Offscreen/fully clipped source or target falls back to a fade unless the application deliberately scrolls it into view first. Arbitrary masks, 3D transforms and cross-document elements require a defined fallback, not incorrect geometry.

**Stacking:** explicit route overlay layer above route content but below modal/top-layer UI and persistent navigation. Preserve deterministic surface < image < title ordering, isolate each scene, avoid enormous global z-index values. Opening a modal during a route transition must either remain above it or settle route motion. A surface overlay should not intercept links during interruption.

**Scroll restoration:** measure in viewport coordinates after SvelteKit restores document scroll; preserve nested scroller positions per history entry and apply them before target capture. Forward detail navigation may go to top, back restores list position. Do not use one global URL-to-scroll map when repeated history entries can have different positions. No simultaneous smooth scroll and geometry morph by default. If user scrolls during playback, remeasure/retarget affected targets from current visuals, or settle immediately if continuity cannot be maintained.

**Delayed data/images/fonts:** route load owns data waiting; source remains live and interactive while pending. Capture just before commit, not at initial click. Destinations reserve layout space. Use source image until target decode, bound readiness waiting (initial prototype budget 800ms after commit), and then settle/fade to a stable placeholder without blocking navigation. Deferred target geometry changes require explicit remeasurement; no guessed 480ms handoff TTL. Failed/missing target pair degrades independently. Cache fonts/preload route data where possible; do not animate into unknown text dimensions.

**Back/forward:** same identity pairing and session lifecycle, driven by navigation type/history entry, not click listeners. Handle browser controls, programmatic navigation, redirects, canceled navigation, deep links and BFCache. Deep links without source render normally. Clean temporary styles on pagehide/pageshow restoration.

**Rapid repeated navigation:** monotonically increasing session generation and abort signal. Latest committed navigation wins. Capture live overlay boxes/crop/opacity before canceling its effects; transfer those visuals to the next session when identities match. Stale finish/decode/load callbacks cannot reveal or remove newer visuals. Bound retained layers to the active entity plus one outgoing content generation. If an entity changes, fade unmatched parts while preserving matched ones. Carry track velocity into the new trajectory. A pending destination freezes the current visual while readiness resolves; it does not keep flying toward stale geometry. This holds position but temporarily pauses velocity, an explicit bounded-wait tradeoff.

## Prototype acceptance and resulting decision

The representative evaluation must use real `/list`, `/detail/a`, `/detail/b` client routes, not a boolean swap in one page. Use multiple cards in a scrollable page, a clipped nested media surface, large changed image aspect ratio, and a title whose size/wrapping changes. Keep unrelated Button/Tabs/Popover behavior independent.

| Exercise                                                           | Required observation                                                                                                       |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| List → detail → back                                               | Surface/image/title remain related; exact resting geometry; no glyph stretching/crop snap; list scroll restored            |
| Interrupt at 25%, 50%, 75% and navigate A → B → list               | Next first frame starts at previous visual position within 1 CSS px where pair matches; no ignored input; no stale cleanup |
| Browser back/forward during pending load and playback              | URL/history/selected entity correct; motion never deadlocks routing                                                        |
| Delay data >480ms; delayed/failed image and late font/layout shift | Stable reserved layout; source usable while load waits; bounded visual readiness; explicit fallback                        |
| Nested scroller, clipping, sticky header/modal                     | Coordinate and z-order correct; no escaped clip or double parent motion                                                    |
| User scroll / viewport resize during playback                      | Retarget from live state or documented immediate settlement, no destination jump                                           |
| Reduced motion at start and switched mid-flight                    | No moving layers; final DOM immediately usable; no retained overlay/hidden destination                                     |
| Repeat 20 cycles                                                   | No stale observers, retained images, hidden nodes or active animations; no console/network failures                        |

The expanded [evaluation](motion-architecture-evaluation.md) records these checks, including actual network throttling, OS media reduction, nested scroll restoration and BFCache. **Choose the JS-coordinated, part-specific WAAPI architecture for route motion.** Keep the local layout engine for current shared-layout consumers; remove it from simple measured indicators during a subsequent component migration. Do not replace it wholesale with Astra on the strength of route tests: that would be a separate local-layout backend change.

The prototype contract is one selected, scoped entity with surface/image/title parts, DOM-derived clip ancestry and at most eight rectangular or uniformly rounded clip ancestors. It rejects ambiguous/missing registrations and unsupported 3D, scale/rotation, arbitrary mask/clip-path geometry with an entity-level fade/settlement. It is not a universal renderer for arbitrary CSS. These are explicit supported-behavior decisions, not silent visual corruption or reasons to make ordinary components depend on the route subsystem. The production registry should expose these same constraints as typed participant options, not infer universal support from a generic shared ID.
